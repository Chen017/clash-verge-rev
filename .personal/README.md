# Clash Verge Personal

Unofficial Windows amd64 builds of the latest stable Clash Verge Rev, bundling Chen017/mihomo with independent XHTTP download routing and VLESS 0-RTT ticket recovery. Only one NSIS installer is published. No ARM, 32-bit, MSI, portable or fixed-WebView variants are built.

Install the personal installer once, choosing the current installation directory. Export a configuration backup before migration. The application identifier and configuration directory remain `io.github.clash-verge-rev.clash-verge-rev`; existing providers and selections are retained. The personal stable core is selected automatically, including migration from the old Alpha selection. The two internal core filenames contain the same verified personal binary for installer/service compatibility.

After migration, use the ordinary application updater. Its update feed and permanent signing key belong to this fork. Core-only updates increment `personal.N`, so a changed core is delivered in a new installer without manually replacing files. Updating an administrator-approved service core still uses the existing elevation and rollback mechanism. A core upgrade verifies the release checksum and the actual running core version before reporting success. Windows may request permission to install or approve a service update.

Every six hours, Personal Windows amd64 checks upstream stable releases and the published Chen017/mihomo core. It pins both, applies `.personal/app.patch`, builds/tests just Windows amd64, verifies the actual installer signature (including rejecting corruption), and publishes only a complete draft. Identical inputs skip the build. Conflicting patches or failed checks retain the last usable release. GitHub may suspend scheduled workflows in inactive forks; the Actions page supports manual runs and re-enabling schedules. No artificial keepalive commits are generated.

Maintenance lives on `codex/personal-builds`. Push a changed patch or workflow there. Generated source tags identify the exact app source; `manifest.json` records upstream, actual app source commit, pinned core source provenance and archive checksum. GitHub's source archive for the release tag contains the app source; the linked Chen017/mihomo source tag contains the actual patched core. Generated source keeps upstream workflows unchanged, so publication needs only the built-in repository token's contents permission. Inherited workflows are disabled; only the personal workflow runs.

Secrets `TAURI_SIGNING_PRIVATE_KEY` and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` hold the permanent encrypted Tauri updater key and password. Never regenerate them for an existing installation. The updater public key is in `src-tauri/tauri.conf.json`. This is an updater signature, not a Microsoft Authenticode certificate.
